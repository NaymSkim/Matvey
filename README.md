# Учебный портал по физике

Статический русскоязычный портал для GitHub Pages с защищённой проверкой ответов в Supabase. Публичная часть содержит каталог и условия заданий; ключи, решения, попытки и оценки находятся только в Supabase.

## Что уже реализовано

- вход ученика по имени и восьмизначному коду на нескольких устройствах;
- каталог, поиск, темы и лучший результат;
- одна попытка на вопрос и максимум две сдачи всей работы независимо от варианта;
- серверная проверка без ключей в HTML и JavaScript;
- безопасный повтор ответа после сетевой ошибки с тем же `attemptId`;
- кабинет преподавателя с Magic Link, посещениями, ответами и оценками;
- выпуск нового кода с отвязкой устройств, удаление ученика, выдача решений;
- публикация GitHub Pages только из проверенной папки `dist`;
- локальная сборка Supabase-клиента без зависимости сайта от внешнего CDN;
- ручной экспорт журнала в CSV.

## Структура

- `data/activities.json` — публичный каталог и пороги оценок;
- `data/task-content/` — публичные условия без ответов;
- `answers.private.json` — локальные ключи (исключён из Git);
- `supabase/migrations/` — таблицы, индексы и RLS;
- `supabase/functions/` — защищённая авторизация и проверка;
- `scripts/` — сборка, импорт ключей, создание преподавателя и экспорт;
- `.github/workflows/pages.yml` — проверка и публикация GitHub Pages.

## 1. Подготовить Supabase

1. Создайте бесплатный проект и сохраните его Project ref, URL, publishable key и secret key.
2. В Authentication → Providers включите Anonymous Sign-Ins и Email.
3. В Authentication → URL Configuration укажите будущий адрес Pages как Site URL и добавьте точный адрес `teacher.html` в Redirect URLs.
4. Установите Supabase CLI, затем из папки проекта выполните:

```sh
pnpm install
supabase login
supabase link --project-ref PROJECT_REF
supabase db push --dry-run
supabase db push
supabase functions deploy
supabase secrets set SITE_ORIGIN=https://GITHUB-NAME.github.io
```

`SUPABASE_URL` и набор `SUPABASE_SECRET_KEYS` Supabase предоставляет Edge Functions автоматически. В `SITE_ORIGIN` можно перечислить несколько точных адресов через запятую.

У функций отключена устаревшая платформенная проверка `verify_jwt`: новые publishable keys не являются JWT. Это не делает функции публичными — каждая операция сама требует пользовательский Bearer JWT и проверяет его через Supabase Auth до чтения данных.

## 2. Создать преподавателя и загрузить ответы

Экспортируйте переменные только в локальном терминале; secret key нельзя добавлять в репозиторий:

```sh
export SUPABASE_URL=https://PROJECT.supabase.co
export SUPABASE_SECRET_KEY=sb_secret_...
export TEACHER_EMAIL=teacher@example.com
pnpm run teacher
pnpm run sync
```

Скрипт `teacher` создаёт существующего Auth-пользователя, поэтому `signInWithOtp(... shouldCreateUser: false)` не позволяет постороннему адресу зарегистрировать преподавателя. `sync` загружает каталог и закрытые ключи из локального `answers.private.json`.

## 3. Подключить клиент

Для локального просмотра можно заполнить безопасные публичные значения в `config.js`. Для GitHub Pages лучше оставить файл без значений и создать в Settings → Secrets and variables → Actions → Variables:

- `SUPABASE_URL`;
- `SUPABASE_PUBLISHABLE_KEY`.

Они автоматически подставляются только в публичную сборку. Secret key в GitHub для публикации не требуется.

## 4. Опубликовать

1. Используйте отдельный репозиторий `Matvey` и загрузите в него содержимое этой папки, кроме игнорируемых файлов.
2. В Settings → Pages → Build and deployment выберите **GitHub Actions**.
3. Отправьте изменения в ветку `main`.

Workflow сначала проверит каталог и отсутствие закрытых данных, соберёт `dist`, затем опубликует его. Все ссылки относительные и работают по вложенному адресу GitHub Pages.

## Работа с материалами

После изменения исходных учебных HTML-файлов локально выполните:

```sh
pnpm run content
pnpm run validate
pnpm run build
pnpm run sync
```

`content` заново формирует публичные условия и приватный файл ответов. СР‑1–СР‑10 создаются как десять независимых работ. В CI эта команда намеренно не запускается: исходные старые сайты лежат вне отдельного репозитория, а приватный файл не должен попадать в GitHub.

`sync` выполняется одной транзакцией: удаляет устаревшие ключи и отключает исчезнувшие карточки. Для защиты текущих результатов обновление ключей остановится, если у ученика есть незавершённая сдача.

Для новой работы добавьте карточку в `data/activities.json`, публичный файл условий в `data/task-content/` и ответы только в `answers.private.json`, затем выполните `pnpm run sync`.

## Резервная копия журнала

После значимой работы выполните с локальными `SUPABASE_URL` и `SUPABASE_SECRET_KEY`:

```sh
pnpm run export
```

CSV появится в `exports/` (папка исключена из Git).

## Локальная проверка

```sh
pnpm run validate
pnpm run build
python3 -m http.server 4173 --directory dist
```

Откройте `http://127.0.0.1:4173`. Для полноценного входа добавьте этот origin в `SITE_ORIGIN`; localhost уже разрешён функциями для разработки.

## Важные ограничения

- GitHub Pages не скрывает файлы: секреты и ответы нельзя помещать ни в одну публичную папку.
- Имя и код ученика не заменяют Auth; они только привязывают анонимную JWT-сессию к записи ученика.
- После нового кода все старые устройства отвязываются.
- Официальная оценка вычисляется как лучший процент из двух завершённых сдач всей работы; обе сохраняются.
- Для работы с открытыми вопросами сдача сохраняется без автоматической оценки и считается завершённой.
